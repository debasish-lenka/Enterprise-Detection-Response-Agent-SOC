🔐 Core Security Features

mTLS with Certificate Pinning
Mutual TLS authentication with pinned certificates
✓ CONFIGURED

Policy Signing with Ed25519
Only signed policies are executed by agents
✓ ENFORCED
All policies are cryptographically signed using Ed25519 keys. Unsigned policies are rejected by agents. Policy signatures verified before execution.
Secret Redaction in Logs
Automatic scrubbing of passwords and API keys
✓ ACTIVE
# Patterns detected and redacted: - API Keys: /[\w-]{32,}/g - Passwords: /password.*[:=]\s*"?[^"\s]+/i - Tokens: /token.*[:=]\s*"?[^"\s]+/i - Database URLs: /connection_string=.*/i
Immutable Audit Logging
Tamper-evident event logging
✓ RECORDING
All events are logged with cryptographic hashes for tamper detection. Logs are immutable and cannot be modified after creation. BLAKE3 hashing for integrity verification.
Code Signing on Releases
All releases are GPG signed
✓ ENABLED
All DUEA releases are cryptographically signed with GPG keys. Release signatures can be verified using public key: keys.openpgp.org

🔑 End-to-End Encryption

Sensitive data is never logged in plain text. All credentials are encrypted in transit and at rest.

📝 Immutable Logs

🎯 Threat Model & Mitigations

Agent Compromise

Threat: Attacker gains access to agent and modifies local configuration
Mitigation: Code signing + immutable audit logs + tamper detection

Man-in-the-Middle (MITM)

Threat: Attacker intercepts communication between agent and manager
Mitigation: mTLS with certificate pinning + TLS 1.3 + AES-256 encryption

Policy Injection

Threat: Attacker injects malicious policies to agents
Mitigation: Ed25519 digital signature verification before execution

Lateral Movement

Threat: Compromised endpoint becomes pivot point for network attack
Mitigation: Privilege isolation + capability-based execution + network segmentation
